## 算法 ALG

### ALG-001 二分答案的单调性

- 题目：资源配置随参数变化时，怎样证明可以二分答案而不会漏掉可行解？
- 分类/标签：算法 / 二分查找、边界
- 难度：★★★
- 易错点（常见错误答案）：目标值有大小顺序就能二分，循环退出时返回值一定对应已有元素。
- 正确要点：二分查找（Binary Search）要求判定函数单调；半开区间 `[lo, hi)` 应明确两侧已排除的范围并保证每轮收缩。左边界可能等于 n，空输入和中点计算也要避免下溢、溢出。
- 追问：若可行性先真后假再真，哪个不变量首先失效？
- 来源/日期：面试系列 05 算法与系统设计面试：从解题不变量到 OLAP 与 LLM 服务的容量边界, 2026-10-24

### ALG-002 带负数的最短子数组

- 题目：求和至少为 K 的最短连续子数组，加入负数后双指针为何可能出错？
- 分类/标签：算法 / 滑动窗口、前缀和
- 难度：★★★★
- 易错点（常见错误答案）：和够大就收缩，否则右移，正负数都适用。
- 正确要点：滑动窗口（Sliding Window）的常用收缩规则依赖和的单调变化，负数会破坏它。可对前缀和维护单调队列（Monotonic Queue）：先弹出满足差值的队首更新答案，再移除不可能更优的队尾；每个下标至多进出一次，故总计 O(n)。
- 追问：用 `[1, -1, 5]`、K=5 推演普通窗口为何漏掉长度 1 的解。
- 来源/日期：面试系列 05 算法与系统设计面试：从解题不变量到 OLAP 与 LLM 服务的容量边界, 2026-10-24

### ALG-003 局部词频前 K 的遗漏

- 题目：多个分片分别取词频前 K，再合并候选，何时能保证精确答案？
- 分类/标签：算法 / Top K、分区
- 难度：★★★★
- 易错点（常见错误答案）：任意切分输入后，所有全局热门词都会在某个分片进入前 K。
- 正确要点：前 K 项（Top K）若按频次排序，必须先完成同键计数；K=1 时，两片分别为 x:6、a:7 与 x:6、b:7，局部候选会漏掉全局 x:12。先按完整键归到唯一分区并统一并列排序规则，局部前 K 才能覆盖所需全局候选。
- 追问：要求返回所有并列第 K 名时，候选规模还能限制为 K 吗？
- 来源/日期：面试系列 05 算法与系统设计面试：从解题不变量到 OLAP 与 LLM 服务的容量边界, 2026-10-24

### ALG-004 压缩状态与背包方向

- 题目：0/1 背包把二维表压成一维后，为何容量必须倒序更新？
- 分类/标签：算法 / 动态规划、0/1 背包
- 难度：★★★
- 易错点（常见错误答案）：正序、倒序只影响缓存命中，不影响状态含义。
- 正确要点：动态规划（Dynamic Programming）压缩后必须保留转移依赖的旧状态；倒序使 `dp[c-w]` 仍属于上一轮物品。正序可能读取本轮已更新值，从而重复使用当前物品，改变了题目约束。
- 追问：若要求恢复选取路径，单个最优值数组还缺哪些信息？
- 来源/日期：面试系列 05 算法与系统设计面试：从解题不变量到 OLAP 与 LLM 服务的容量边界, 2026-10-24

### ALG-005 递增子序列的尾值数组

- 题目：最长递增子序列的尾值数组，能直接作为答案序列返回吗？
- 分类/标签：算法 / LIS、路径恢复
- 难度：★★★★
- 易错点（常见错误答案）：每个位置都由原数组元素得到，所以拼起来必然是一条子序列。
- 正确要点：最长递增子序列（Longest Increasing Subsequence，LIS）的尾值数组只记录各长度的最小末尾，不保证各槽位来自同一条路径。严格递增使用首个大于等于目标的位置替换；恢复路径须另存前驱和对应原下标。
- 追问：允许相等的非递减子序列，应改用哪一种边界搜索？
- 来源/日期：面试系列 05 算法与系统设计面试：从解题不变量到 OLAP 与 LLM 服务的容量边界, 2026-10-24

### ALG-006 拓扑排序残留不全是环

- 题目：入度法结束后还有节点未输出，能否把它们全部报告为环成员？
- 分类/标签：算法 / 图、依赖调度
- 难度：★★★★
- 易错点（常见错误答案）：未输出节点都在环上，删除这些节点即可恢复调度。
- 正确要点：拓扑排序（Topological Sort）残留包含环及被环阻塞的下游，例如 a↔b、b→c 中 c 不在环上。定位环可进一步求强连通分量（Strongly Connected Component）；调度还须区分任务成功、失败与依赖解除条件。
- 追问：单节点分量何时也构成环？
- 来源/日期：面试系列 05 算法与系统设计面试：从解题不变量到 OLAP 与 LLM 服务的容量边界, 2026-10-24

### ALG-007 哈希连接的输出成本

- 题目：哈希连接为什么不能无条件写成 O(n+m)，增加分区能否解决所有热点？
- 分类/标签：算法 / 哈希连接、倾斜
- 难度：★★★★
- 易错点（常见错误答案）：哈希查找均摊常数，所以与输出规模、热点分布无关。
- 正确要点：哈希连接（Hash Join）的期望工作量应包含输出 Z，即 O(n+m+Z)，并以合适的哈希分布等为前提。同键热点仍进入同一分区；两侧大量重复可令输出达乘积规模，须区分状态超限与结果爆炸。
- 追问：热点分块处理怎样保证每对匹配恰好输出一次？
- 来源/日期：面试系列 05 算法与系统设计面试：从解题不变量到 OLAP 与 LLM 服务的容量边界, 2026-10-24

### ALG-008 外排归并路数的上限

- 题目：外部排序是否总应一次合并全部有序段，以减少归并轮数？
- 分类/标签：算法 / 外部排序、I/O
- 难度：★★★★
- 易错点（常见错误答案）：归并轮数越少就一定越快，内存只需放一个堆。
- 正确要点：外部排序（External Sorting）的归并路数受各输入缓冲、输出缓冲、文件句柄与设备并发预算约束。若每轮完整读写 N 字节，生成段加 p 轮归并约为 `2N(1+p)` 字节；末轮流式输出可省一次物化写入，少轮次也不保证低等待。
- 追问：远端小请求很多时，增大单路缓冲为何可能比增大路数有效？
- 来源/日期：面试系列 05 算法与系统设计面试：从解题不变量到 OLAP 与 LLM 服务的容量边界, 2026-10-24

### ALG-009 过滤器删除与发布

- 题目：标准 Bloom Filter 为何不能直接清位删除，构建正确是否就没有线上漏数？
- 分类/标签：算法 / Bloom Filter、集合语义
- 难度：★★★★
- 易错点（常见错误答案）：误判率很低，所以清除该键对应的位不会影响其他键。
- 正确要点：布隆过滤器（Bloom Filter）中多个键共享位，清位可能使其他已存在键被误判为不存在。理论无假阴性还依赖完整构建与正确发布；新数据已可见而过滤器未覆盖时，必须更新覆盖版本或旁路过滤。
- 追问：Cuckoo Filter 一次查询为阳性，是否就能安全删除该键？
- 来源/日期：面试系列 05 算法与系统设计面试：从解题不变量到 OLAP 与 LLM 服务的容量边界, 2026-10-24

### ALG-010 草图合并不等于可撤回

- 题目：HyperLogLog 能合并每日去重状态，为什么不能从七日状态中减掉第一天？
- 分类/标签：算法 / HyperLogLog、增量计算
- 难度：★★★★
- 易错点（常见错误答案）：并集能合并，因此过期时把昨天的估计数减去即可。
- 正确要点：HyperLogLog 逐寄存器保留最大秩，丢失了元素归属和次大值，普通状态没有任意撤回的逆运算。应合并仍有效的时间桶，且哈希、种子、精度和编码必须兼容；估计数相加也无法处理跨桶重复。
- 追问：滑动窗口更细时，如何权衡桶数量、边界精度和重合并成本？
- 来源/日期：面试系列 05 算法与系统设计面试：从解题不变量到 OLAP 与 LLM 服务的容量边界, 2026-10-24

### ALG-011 负权边与最短路

- 题目：没有负环但存在负权边，Dijkstra 算法还能保证正确吗？
- 分类/标签：算法 / Dijkstra、算法前提
- 难度：★★★★
- 易错点（常见错误答案）：只要不存在负环，第一次弹出的最短距离就不会改变。
- 正确要点：Dijkstra 的定型证明要求相关边权非负；例如 s→a 为 2、s→b 为 5、b→a 为 -4，a 提前定型会出错。存在负边可按约束选择 Bellman–Ford，或在有向无环图（Directed Acyclic Graph）上按拓扑序松弛，不能混用前提。
- 追问：允许反复重新入队是否仍有 Dijkstra 的复杂度保证？
- 来源/日期：经典易错题, 2026-10-24

### ALG-012 快速选择的最坏代价

- 题目：快速选择找第 K 小，期望线性意味着单次请求也有线性上界吗？
- 分类/标签：算法 / Quickselect、复杂度
- 难度：★★★★
- 易错点（常见错误答案）：每轮丢掉一侧，所以无论枢轴怎样选都是 O(n)。
- 正确要点：快速选择（Quickselect）在随机枢轴等假设下期望 O(n)，极端不平衡划分可退化到 O(n²)。中位数的中位数（Median of Medians）可提供最坏线性选择；工程上也可设置退化检测与回退，另计有序输出成本。
- 追问：大量相等元素时，三路划分如何避免无效递归？
- 来源/日期：经典易错题, 2026-10-24

## 操作系统 OS

### OS-001 配额下的空闲处理器

- 题目：主机处理器利用率不高，容器线程为何仍长时间排队？
- 分类/标签：操作系统 / Linux、调度
- 难度：★★★★
- 易错点（常见错误答案）：主机还有空闲核，增加工作线程就能消除等待。
- 正确要点：控制组（Control Group，cgroup）的处理器配额和允许核集合限制实际预算；配额耗尽会节流（Throttling），主机均值不能代表容器可运行资源。应结合可运行队列、节流计数与锁持有者调度情况定位，线程增加可能扩大争抢。
- 追问：若锁持有者被节流，等待线程增加为何会放大尾延迟？
- 来源/日期：面试系列 04 操作系统与网络面试：从调度、内存到 RPC 背压的 Staff 追问链, 2026-10-24

### OS-002 分配成功与首次触页

- 题目：大块分配很快，第一次扫描却很慢，是否能判定是磁盘换入？
- 分类/标签：操作系统 / Linux、虚拟内存
- 难度：★★★
- 易错点（常见错误答案）：分配返回时所有物理页已就绪，缺页都要访问磁盘。
- 正确要点：虚拟内存（Virtual Memory）的地址空间承诺不等于物理页已分配，首次访问可能触发按需分配与清零。次缺页（Minor Page Fault）通常不需磁盘读取，主缺页（Major Page Fault）才涉及相应 I/O；还应区分回收与交换压力。
- 追问：预触页把成本移到何处，是否保证后续不会被回收？
- 来源/日期：面试系列 04 操作系统与网络面试：从调度、内存到 RPC 背压的 Staff 追问链, 2026-10-24

### OS-003 大页与尾延迟

- 题目：透明大页提高吞吐后，为何有些请求延迟反而上升？
- 分类/标签：操作系统 / Linux、THP
- 难度：★★★★
- 易错点（常见错误答案）：页越大越好，只会提高地址转换效率。
- 正确要点：透明大页（Transparent Huge Pages，THP）可减少地址转换后备缓冲（Translation Lookaside Buffer，TLB）压力，但分配、内存规整和拆页可能引入停顿。应固定内核配置与访问模式，对照缺页、规整事件和延迟分布；收益不能由页大小直接推断。
- 追问：稀疏访问大地址空间时，大页会怎样改变实际内存占用？
- 来源/日期：面试系列 04 操作系统与网络面试：从调度、内存到 RPC 背压的 Staff 追问链, 2026-10-24

### OS-004 直接 I/O 与持久化

- 题目：数据库用 O_DIRECT 绕过页缓存，写调用返回后是否就可确认持久化？
- 分类/标签：操作系统 / Linux、O_DIRECT
- 难度：★★★★
- 易错点（常见错误答案）：不经过页缓存就是直接落盘，不必再同步。
- 正确要点：直接输入输出（Direct I/O）主要改变缓存路径，并不自动提供同步持久化保证；对齐、文件系统和设备支持也有限制。确认边界还需按接口使用 `fsync`、`fdatasync` 或相应同步标志，并核对设备缓存与错误返回。
- 追问：数据文件同步成功后，新建文件的目录项是否也必然持久？
- 来源/日期：面试系列 04 操作系统与网络面试：从调度、内存到 RPC 背压的 Staff 追问链, 2026-10-24

### OS-005 完成接口也会排队

- 题目：使用 io_uring 后，能否推断所有操作均由设备异步执行且没有工作线程？
- 分类/标签：操作系统 / Linux、io_uring
- 难度：★★★★
- 易错点（常见错误答案）：提交不阻塞，所以内核不会为这些操作阻塞线程。
- 正确要点：io_uring 提供提交与完成机制，具体操作可能走内核工作线程，轮询模式也有处理器成本。须区分提交队列等待、实际执行与完成消费，并按操作类型、内核版本和注册选项验证；异步接口不消除下游瓶颈。
- 追问：完成队列无人消费时，缓冲区和在途上限由谁回收？
- 来源/日期：面试系列 04 操作系统与网络面试：从调度、内存到 RPC 背压的 Staff 追问链, 2026-10-24

### OS-006 边沿触发的排空条件

- 题目：边沿触发 epoll 每次只读一个消息，然后等待下次通知，为什么可能卡住？
- 分类/标签：操作系统 / Linux、epoll
- 难度：★★★★
- 易错点（常见错误答案）：只要描述符仍可读，下一轮一定会再通知。
- 正确要点：边沿触发（Edge-Triggered）通常需配合非阻塞描述符，持续读取直到 `EAGAIN`，否则剩余数据可能没有新边沿。`EINTR`、对端关闭和应用分帧要分别处理；若为公平性提前让出，应自行保留可继续执行的状态。
- 追问：写缓冲非空时，何时订阅和取消可写通知以避免忙循环？
- 来源/日期：面试系列 04 操作系统与网络面试：从调度、内存到 RPC 背压的 Staff 追问链, 2026-10-24

### OS-007 发送成功不等于业务提交

- 题目：TCP 的 send 成功、收到传输确认、收到业务响应，分别证明什么？
- 分类/标签：操作系统 / TCP、确认边界
- 难度：★★★★
- 易错点（常见错误答案）：send 成功表示对端应用收到并处理了全部请求。
- 正确要点：传输控制协议（Transmission Control Protocol，TCP）是字节流，send 成功通常只说明相应字节被本地协议栈接受；传输确认也不等于业务提交。消息边界由应用编码，业务响应能否代表持久提交取决于服务端契约。
- 追问：响应丢失时，客户端怎样区分未执行与已提交？
- 来源/日期：面试系列 04 操作系统与网络面试：从调度、内存到 RPC 背压的 Staff 追问链, 2026-10-24

### OS-008 多线程进程中的 fork

- 题目：多线程进程 fork 后，子进程为何可能在日志输出或分配内存时死锁？
- 分类/标签：操作系统 / POSIX、进程创建
- 难度：★★★★★

### DIST-002 恰好一次依赖提交边界

- 题目：消费端先提交业务结果，再提交消息位点，为什么崩溃后仍可能重复生效？
- 分类/标签：分布式 / 消息处理、恢复
- 难度：★★★★★
- 易错点（常见错误答案）：位点能记录进度，两个提交先后完成就是恰好一次。
- 正确要点：恰好一次（Exactly-Once）语义需说明覆盖边界；结果和位点分离提交时存在结果已生效而位点未推进的崩溃窗口。可在同一事务内提交，或以稳定标识做原子去重；外部副作用未纳入协议时不能扩大承诺。
- 追问：先提交位点再写结果，会把重复风险换成什么风险？
- 来源/日期：面试系列 02 数据库内核面试：沿查询、视图维护与恢复解释正确性, 2026-10-24

### DIST-003 缓存击穿后的源站预算

- 题目：缓存节点失效后，为什么自动回源和重试可能拖垮原本健康的数据库？
- 分类/标签：分布式 / 缓存、过载
- 难度：★★★★
- 易错点（常见错误答案）：缓存只影响命中率，源站能够接收剩余请求即可。
- 正确要点：缓存击穿（Cache Stampede）可让同一热点的并发请求集中回源，故障还可能放大重试流量。需按源站容量限制在途请求，合并同键加载并设计拒绝、过期数据或降级策略；仅增加缓存副本不消除冷启动洪峰。
- 追问：合并请求的首个加载失败时，等待者应怎样重试以避免再次集中冲击？

### DIST-004 滚动升级的双向兼容

- 题目：新服务能读旧协议，是否就足以保证滚动升级可用且能回滚？
- 分类/标签：分布式 / 协议、版本倾斜
- 难度：★★★★
- 易错点（常见错误答案）：兼容老客户端只需新版本支持旧字段。
- 正确要点：版本倾斜（Version Skew）还包括旧执行器读新计划、新节点写入旧节点不能恢复的持久状态。应约束能力协商、未知字段与枚举处理，并在全体具备能力后启用新格式；回滚需要反向读写兼容或明确停止点。
- 追问：删除字段与复用旧字段编号，哪一种更容易造成静默语义错误？

### DIST-005 过载时排队必须有界

- 题目：入口持续接受请求并排队，是否比立即拒绝更能提高成功率？
- 分类/标签：分布式 / 背压、截止时间
- 难度：★★★★
- 易错点（常见错误答案）：排队不丢请求，后端迟早会追上。
- 正确要点：背压（Backpressure）要让下游容量限制传播到上游；持续到达率超过服务率时，无界队列只会累计等待与内存。应限定队列和在途资源，传播截止时间并丢弃已无成功预算的工作，重试还须有预算与退避。
- 追问：客户端已超时的请求为什么可能继续消耗整个集群？

### DIST-006 旧任期日志的提交限制

- 题目：Raft 新领导者发现旧任期条目已复制到多数节点，能否单凭该计数提交它？
- 分类/标签：分布式 / Raft、日志提交
- 难度：★★★★★
- 易错点（常见错误答案）：多数节点有副本就不可能被覆盖，与条目任期无关。
- 正确要点：Raft 不能仅凭副本计数直接提交旧任期条目；领导者用此规则推进提交位置时，所选条目必须属于当前任期。当前任期条目在多数上复制并提交后，其之前的日志才随此前缀间接提交，选举与日志匹配共同保证安全。 参见[Raft 论文 §5.4.2](https://raft.github.io/raft.pdf)。
- 追问：新领导者为何常先追加当前任期的空操作？
- 来源/日期：经典易错题, 2026-10-24

### DIST-007 领导者本地读也可能过期

- 题目：曾当选领导者的节点，能否不与其他节点通信就持续提供线性一致读？
- 分类/标签：分布式 / Raft、线性一致性
- 难度：★★★★★
- 易错点（常见错误答案）：只要进程未主动降级，它的日志就是最新值。
- 正确要点：线性一致性（Linearizability）要求读尊重已完成写的实时顺序；失联旧领导者可能不知道新领导者已经完成写。读协议通常需确认当前领导权并等状态机应用到安全读位置；租约方案还依赖时钟和租约约束，不能凭本地角色位判断。 参见[Raft 论文 §8](https://raft.github.io/raft.pdf)。
- 追问：多数确认后本地 apply 仍落后，立即读取状态机会违反什么？
- 来源/日期：经典易错题, 2026-10-24

### DIST-008 过期持锁者需要隔离

- 题目：分布式锁租约到期后，新客户端已获锁，旧客户端从长暂停恢复还能写吗？
- 分类/标签：分布式 / 租约、Fencing Token
- 难度：★★★★★
- 易错点（常见错误答案）：锁服务已让旧租约失效，旧进程的所有后续操作都会被自动拒绝。
- 正确要点：租约（Lease）失效不会自动撤销已发出或即将发出的存储操作。可由锁服务产生单调递增的隔离令牌（Fencing Token），并让实际资源端拒绝旧令牌；只在客户端检查锁状态仍存在检查与使用之间的窗口。
- 追问：若存储端不校验令牌，单靠延长租约能否证明互斥？
- 来源/日期：经典易错题, 2026-10-24

### DIST-009 CAP 的分区前提

- 题目：CAP 是否意味着系统无论何时都必须从三个属性中永久选两个？
- 分类/标签：分布式 / 一致性、可用性
- 难度：★★★★
- 易错点（常见错误答案）：复制系统只能同时具备两个属性，正常网络时也一样。
- 正确要点：CAP 定理（CAP Theorem）讨论网络分区下，线性一致语义与每个非故障节点都需响应的可用性要求之间的冲突。需要根据操作和分区策略说明拒绝或返回什么；工程成功率目标也不等同于定理的可用性定义。
- 追问：少数派拒绝写入，多数派继续服务，保留了什么又放弃了什么？
- 来源/日期：经典易错题, 2026-10-24

### DIST-010 两阶段提交的阻塞窗口

- 题目：两阶段提交的参与者已投赞成票，协调者失联时能否超时后自行回滚？
- 分类/标签：分布式 / 事务、2PC
- 难度：★★★★★
- 易错点（常见错误答案）：没有收到提交指令，就说明还未提交，可以直接回滚。
- 正确要点：两阶段提交（Two-Phase Commit，2PC）进入准备状态后，其他参与者可能已收到提交决定；单方回滚会破坏原子性。恢复需查询或恢复持久化决定；复制协调状态能改善故障恢复，但不能把所有网络分区下的等待都消除。
- 追问：参与者何时可安全回答“我尚未准备，因此可以终止”？
- 来源/日期：经典易错题, 2026-10-24

### DIST-011 跨分片读需要共同切面

- 题目：每个分片各自返回一个本地一致快照，合并后是否就是全局一致查询？
- 分类/标签：分布式 / 快照、读一致性
- 难度：★★★★★
- 易错点（常见错误答案）：局部读都无脏数据，拼起来也不会出现异常。
- 正确要点：各分片独立选时间可能让查询同时看到转账扣款后的 A 与入账前的 B。跨分片快照（Distributed Snapshot）需共同的可见性切面或等效协调协议，并处理未完成事务；本地一致性不能推导全局一致性。
- 追问：全局读时间已确定后，某分片尚未追到该时间，应等待还是降级语义？

### DIST-012 墙钟不能判定因果

- 题目：用各节点本地时间戳排序事件，能否准确恢复因果先后？
- 分类/标签：分布式 / 时钟、因果关系
- 难度：★★★★
- 易错点（常见错误答案）：时间精度足够高且部署了校时，时间较小就一定先发生。

### AI-001 KV 容量必须按模型结构计算

- 题目：估算大语言模型服务的每请求 KV 显存，为什么不能只乘模型参数量或查询头数？
- 分类/标签：AI Infra / LLM Serving、KV Cache
- 难度：★★★★
- 易错点（常见错误答案）：权重放得下就能服务任意并发，KV 总是按全部注意力头存储。
- 正确要点：大语言模型（Large Language Model，LLM）常规全层解码器的键值缓存（Key-Value Cache，KV Cache）逻辑字节数约为 `2×层数×已缓存词元数×KV头数×头维度×每元素字节数`。还须计块浪费、元数据与实现复制；分组查询注意力（Grouped-Query Attention，GQA）使用 KV 头数，压缩潜在状态等其他结构须另建公式。
- 追问：张量并行中 KV 头数少于设备数时，分片还是复制会怎样改变每卡预算？

### AI-002 块化状态不改变逻辑容量

- 题目：PagedAttention 是否把每个词元的逻辑 KV 大小压缩了，也自动消除了内存不足？
- 分类/标签：AI Infra / PagedAttention、显存
- 难度：★★★★
- 易错点（常见错误答案）：分页以后 KV 像磁盘虚拟内存一样几乎不占显存。
- 正确要点：PagedAttention 按块管理 KV 的物理位置与共享，减少预留浪费和重复状态，未自动改变模型所需的每词元逻辑状态。块表、尾块浪费、活跃块和其他运行内存仍占预算，超额服务仍需准入或抢占策略。 参见[PagedAttention 论文](https://arxiv.org/abs/2309.06180)。

### AI-003 分块预填充的收益归属

- 题目：将长输入预填充分块后，首词和后续词延迟为什么可能一升一降？
- 分类/标签：AI Infra / 调度、Chunked Prefill
- 难度：★★★★
- 易错点（常见错误答案）：块越小越公平，所有延迟和吞吐都会同时改善。
- 正确要点：分块预填充（Chunked Prefill）缩短单轮长输入占用时间，可减少对已有解码的干扰，但新增轮次与调度开销可能拖慢该请求首词。需在混合输入与输出长度分布下，联合测量首词时延（Time to First Token，TTFT）、词间时延（Inter-Token Latency，ITL）及满足目标的吞吐。

### AI-004 前缀相似不等于可复用

- 题目：语义相似但词元序列不同的提示，能否直接共享已有 KV？

### AI-005 远端命中未必更快

### AI-010 量化对象与容量不能混算

- 题目：权重从 16 位改成 4 位，能否推断整机显存变成四分之一且输出质量不变？
- 分类/标签：AI Infra / Quantization、权重、KV
- 难度：★★★★
- 易错点（常见错误答案）：模型位宽缩小四倍，所有显存和传输都同比缩小。
- 正确要点：量化（Quantization）必须区分权重、激活和 KV；权重量化不自动缩小 KV，尺度、分组元数据和工作区也占空间。数值扰动可能影响质量，执行内核与反量化成本影响性能，应分别验证容量、时延与目标任务质量。

### AI-011 向量过滤后的召回语义

- 题目：近似向量检索先取 k 个候选再按租户过滤，是否等于在该租户内求前 k？
- 分类/标签：AI Infra / ANN、过滤、Recall
- 难度：★★★★
- 易错点（常见错误答案）：全局最近的结果包含局部最近，过滤后有多少返回多少即可。
- 正确要点：近似最近邻（Approximate Nearest Neighbor，ANN）后过滤可能把多数候选删除，即使返回不足 k 条也不代表合格集合不足。召回率（Recall）真值应在相同过滤、快照与距离规则下精确计算；过采样只能缓解，任意选择率下没有固定倍数保证。
- 追问：合格集合很小时，何时精确扫描比图索引更合适？

### AI-012 工具重试不能重放副作用

- 题目：智能体调用扣款工具超时，是否可以把同一步交给模型再次调用？
- 分类/标签：AI Infra / Agent Runtime、恢复

- 易错点（常见错误答案）：模型重新规划会理解失败原因，不需要持久化工具执行状态。
